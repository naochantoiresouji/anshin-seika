# プログラム仕様書：あんしん正価モデル 経済検証シミュレーション（v1.0）

## 1. 概要と目的
本プログラムは、公的個人認証（JPKI）およびゼロ知識証明（ZKP）を用いたチケット流通適正化フレームワーク「あんしん正価モデル」において、**単発の抽選販売イベントにおける購入者（一般消費者 vs 大量応募を行う二次流通目的の購入者）の期待収益（ROI）とコスト構造の非対称性**を検証する決定論的数理モデル（v1）である。

### v1のスコープ（前提条件）
* **対象イベント:** 単発（ワンショット）の抽選販売イベント1回分のみを扱う。複数公演（ツアー等）での同一名義使い回しによる名義調達コストの按分（希釈）およびプロトコル側の重複当選ロック（ノードロック）は、v2以降の拡張対象とする。
* **確率モデル:** 乱数シミュレーション（モンテカルロ法）ではなく、当選確率に基づく**期待値計算（決定論的モデル）**を採用する。
* **市場価格:** 現実には当選率（倍率）に応じて二次流通の市場価格も変動するが、v1では当選率低下に伴う**コスト構造の変化を純粋に検証するため、二次流通の想定販売価格を固定値**としている（価格弾力性や需給連動のダイナミックプライシングはv2以降の拡張対象とする）。
* **認証単位:** 1口の抽選応募につき、1名義（1枚のマイナンバーカードによるZKP生成）が必要となる。

## 2. 入力パラメータおよび設定定数定義

すべての金額単位は「円（JPY）」、確率は「0.0 〜 1.0 の浮動小数点数」とする。

### 2.1. シミュレーション入力パラメータ（`SimulationConfig`）

| 変数名 | 型 | デフォルト値 | 説明 | 制約条件 |
| :--- | :--- | :--- | :--- | :--- |
| `face_value` | `int` | `10000` | チケット1枚あたりの定価（円） | `face_value >= 0` |
| `resale_price` | `int` | `30000` | 二次流通市場での想定販売価格（円） | `resale_price >= 0` |
| `resale_fee_rate` | `float` | `0.10` | 二次流通プラットフォーム手数料率（例: 10%なら0.10） | `0.0 <= resale_fee_rate < 1.0` |
| `token_fee` | `int` | `200` | 1口応募あたりのZKPトークン発行手数料（円・返金不可） | `token_fee >= 0` |
| `win_rate` | `float` | `0.20` | 1口あたりの当選確率（例: 倍率5倍なら0.20） | `0.0 < win_rate <= 1.0` |
| `self_quota` | `int` | `2` | 自分のカード・家族等で無料調達できる「自前枠」の上限口数 | `self_quota >= 0` |
| `id_procurement_cost` | `int` | `3000` | 自前枠を超えた1口（1人）あたりの名義借り・認証代行コスト（円） | `id_procurement_cost >= 0` |
| `application_counts` | `list[int]` | `[1, 2, 10, 50, 100]` | シミュレーションを実行する応募口数（プレイヤー規模）のリスト | 各要素 `n >= 1` |
| `export_md` | `bool` | `EXPORT_RESULT_MD` | 実行結果をMarkdownファイルへ保存するかどうかのフラグ | `True` または `False` |

### 2.2. ファイル出力切り替え定数（ソースコード冒頭定義）

| 定数名 | 型 | デフォルト値 | 説明 |
| :--- | :--- | :--- | :--- |
| `EXPORT_RESULT_MD` | `bool` | `False` | `True` に変更すると、標準出力と同じレポート内容をスクリプトと同フォルダ内のファイルへ出力する |
| `RESULT_MD_FILENAME` | `str` | `"result.md"` | ファイル出力時の出力先ファイル名 |

## 3. 計算ロジック（数式定義）

応募口数を $N$ （`n`）としたとき、以下の手順で期待値を算出する。

### 3.1. 応募段階の確定コスト（サンクコスト）
当選・落選にかかわらず、応募時点で確実に発生するコスト。

1. **トークン発行コスト ($C_{\text{token}}$)**
   $$C_{\text{token}} = N \times \text{token\_fee}$$

2. **名義調達コスト ($C_{\text{id}}$)**
   自前枠（`self_quota`）までは0円、超過分に対して1人あたりの調達コストが発生する。
   $$C_{\text{id}} = \max(0, N - \text{self\_quota}) \times \text{id\_procurement\_cost}$$

3. **総応募コスト ($C_{\text{entry}}$)**
   $$C_{\text{entry}} = C_{\text{token}} + C_{\text{id}}$$

### 3.2. 当選時の期待値計算
1. **期待当選枚数 ($E_{\text{wins}}$)**
   $$E_{\text{wins}} = N \times \text{win\_rate}$$

2. **チケット本体購入費の期待値 ($C_{\text{ticket}}$)**
   $$C_{\text{ticket}} = E_{\text{wins}} \times \text{face\_value}$$

3. **総投資コスト期待値 ($C_{\text{total}}$)**
   $$C_{\text{total}} = C_{\text{entry}} + C_{\text{ticket}}$$

### 3.3. 収益とROI（二次流通目的の購入者視点）
1. **1枚あたりの二次流通純売上 ($R_{\text{unit}}$)**
   $$R_{\text{unit}} = \text{resale\_price} \times (1 - \text{resale\_fee\_rate})$$

2. **総売上期待値 ($R_{\text{total}}$)**
   $$R_{\text{total}} = E_{\text{wins}} \times R_{\text{unit}}$$

3. **純利益期待値 ($\Pi$)**
   $$\Pi = R_{\text{total}} - C_{\text{total}}$$

4. **投資対効果（ROI: %）**
   $$\text{ROI} = \left( \frac{\Pi}{C_{\text{total}}} \right) \times 100$$

5. **【参考指標】損益分岐点となる最低販売価格 ($P_{\text{breakeven}}$)**
   期待利益 $\Pi = 0$ となるために必要な1枚あたりの二次流通販売価格。
   $$P_{\text{breakeven}} = \frac{\text{face\_value} + \left( \frac{C_{\text{entry}}}{E_{\text{wins}}} \right)}{1 - \text{resale\_fee\_rate}}$$

## 4. 出力仕様

コンソール（標準出力）に以下の2つのセクションを見やすく整形（Markdownテーブル形式）して出力する。また、ソースコード内の切り替えスイッチ `EXPORT_RESULT_MD` が `True` に設定されている場合は、スクリプトと同じディレクトリ内に `result.md` を生成し、標準出力と同一の内容を UTF-8 で書き出す。

### 4.1. 前提条件サマリー
入力されたパラメータの一覧、および現行システム（`token_fee = 0`, `id_procurement_cost = 0`）における1枚あたりの二次流通粗利を表示する。

### 4.2. 応募口数（プレイヤー規模）別の比較テーブル
`application_counts` の各 $N$ について、以下の列を出力する（フォーマット例はデフォルト設定・$N=100$ の場合）。

| 列名 | 説明 | フォーマット例 |
| :--- | :--- | :--- |
| `応募口数 (N)` | プレイヤーの応募総数（1〜2は一般消費者、10以上は大量応募を行う購入者を想定） | `100 口` |
| `期待当選数` | $E_{\text{wins}}$ | `20.0 枚` |
| `応募時確定コスト` | $C_{\text{entry}}$（内訳としてトークン料・名義調達費を併記） | `314,000 円 (20,000 + 294,000)` |
| `総投資コスト期待値` | $C_{\text{total}}$ | `514,000 円` |
| `期待純利益` | $\Pi$（マイナスの場合は赤字であることが明確にわかる表記） | `+26,000 円` |
| `期待ROI` | $\text{ROI}$ | `+5.1 %` |
| `損益分岐転売価格` | $P_{\text{breakeven}}$（この価格以上で売却できないと赤字になるライン） | `28,556 円` |

## 5. エッジケースとバリデーション定義

不正な値によるゼロ除算や論理破綻を防ぐため、計算実行前に `SimulationConfig.validate()` で以下のバリデーションを行う（CLI実行時はバリデーションエラーを `argparse` のエラーメッセージとして標準エラー出力に表示し、終了コード `2` で終了する）。

1. **当選確率が0以下または1超過 (`win_rate <= 0.0` or `win_rate > 1.0`)**
   * `ValueError` を送出し、「当選確率（win_rate）は 0 より大きく 1.0 以下の値で指定してください。」と表示して終了する（ゼロ除算防止）。
2. **手数料率が0未満または100%以上 (`resale_fee_rate < 0.0` or `resale_fee_rate >= 1.0`)**
   * `ValueError` を送出し、「手数料率（resale_fee_rate）は 0.0 以上 1.0 未満の値で指定してください。」と表示して終了する（$P_{\text{breakeven}}$ のゼロ除算防止）。
3. **応募口数が0以下 (`n <= 0`)**
   * `ValueError` を送出し、「応募口数（application_counts）は1以上の整数リストで指定してください。」と表示して終了する。
4. **総投資コストが0円 (`C_total == 0`)**
   * 定価0円（無料チケット）かつトークン料0円・名義調達費0円の場合、ROI計算の分母が0になるため、`ROI` は `N/A (0.0%)` として扱う。
5. **期待当選枚数が1枚未満 (`E_wins < 1.0`)**
   * 一般消費者（$N=1$, `win_rate=0.2` など）では $E_{\text{wins}} = 0.2$ となるが、切り捨て（`int`化）は行わず、浮動小数点のまま期待値計算を継続する（期待値モデルとしての整合性を保つため）。

## 6. コマンドラインインターフェース（CLI）仕様

標準ライブラリ `argparse` を使用し、実行時にすべての入力パラメータを上書き可能とする。引数を省略した場合はデフォルト値が適用される。

### 6.1. オプション一覧

| オプション名 | 短縮/別名 | 対応変数 | 型 | デフォルト値 |
| :--- | :--- | :--- | :--- | :--- |
| `--face-value` | なし | `face_value` | `int` | `10000` |
| `--resale-price` | なし | `resale_price` | `int` | `30000` |
| `--resale-fee-rate` | なし | `resale_fee_rate` | `float` | `0.10` |
| `--token-fee` | なし | `token_fee` | `int` | `200` |
| `--win-rate` | なし | `win_rate` | `float` | `0.20` |
| `--self-quota` | なし | `self_quota` | `int` | `2` |
| `--id-procurement-cost` | `--id-cost` | `id_procurement_cost` | `int` | `3000` |
| `--application-counts` | `--counts` | `application_counts` | `int`（複数指定可） | `1 2 10 50 100` |

### 6.2. 実行例

```bash
# デフォルト設定で実行
python anshin_seika_sim.py

# 1公演あたり名義コスト1,000円（複数公演按分想定）・当選率8%（倍率12.5倍）で検証
python anshin_seika_sim.py --win-rate 0.08 --id-cost 1000

# 1口〜5口まで細かく刻んで検証
python anshin_seika_sim.py --counts 1 2 3 4 5
